# WEI LAN 海外站 SEO 效果周报

只读取以下两个数据文件，禁止猜测或读取任何带时间戳的报告文件名：

- `monitor/reports/weekly-history.json`：最多包含最近 7 个按时间排序的每日技术监控快照。
- `monitor/reports/gsc-latest.json`：Google Search Console 最近完整 7 天、前 7 天、查询词和着陆页数据。

必须使用简体中文输出。URL、产品名、关键词和必要的技术字段可以保留英文。

报告主体只分析自然搜索效果：Google Search Console 的曝光、点击、CTR、平均排名、查询词和着陆页表现。技术监控只用于识别会直接影响抓取、收录和排名的异常，包括 HTTP 状态、异常重定向、索引指令、canonical、hreflang、robots.txt 和 sitemap。

周报不分析 PageSpeed、Core Web Vitals、服务器响应速度、TLS、询盘或转化数据。不得用“页面正常”代替“SEO 效果好”，不得虚构任何指标。

分析 GSC 数据时必须遵守：

- 明确写出当前统计周期和对比周期，不把数据延迟误判为流量下降。
- 点击、曝光、CTR 和平均排名以 `current_period.totals` 为准。
- 环比变化以 `comparison` 为准；百分比为 `null` 时写“上期为 0，无法计算百分比”。
- 排名数以 `keyword_position_counts` 为准，着陆页数以 `organic_landing_page_count` 为准。
- GSC 会因隐私保护隐藏低流量查询词。必须结合 `query_coverage` 说明可见查询曝光占比；`keyword_position_counts` 仅代表可见查询词，不能写成全站全部关键词数量。
- 从 `queries` 和 `landing_pages` 中提炼表现最好及需要优化的项目，不能只罗列总数。
- 优先分析 `opportunity_queries`，但如果为空，必须如实写“当前周期未发现符合阈值的机会词”。
- 平均排名数值越小越好；判断变化时不得把排名数值上升误写为排名改善。

## 固定报告结构

1. **本周 SEO 效果结论**
   - 用 3 至 5 条结论直接评价曝光、点击、CTR、排名和有效着陆页表现。
   - 结论必须直接回答“当前效果怎么样”，避免只罗列数据。
2. **核心 SEO 指标表**
   - 当前 7 天与前 7 天的曝光、点击、CTR、平均排名及环比变化。
   - 可见查询词进入前 10/20/50 的数量、自然搜索着陆页数量和查询词披露比例。
   - 不得加入 PageSpeed、Core Web Vitals、响应时间、TLS 或转化指标。
3. **搜索趋势与异常**
   - 搜索效果对比当前 7 天和前 7 天，结合每日曝光、点击变化解释趋势。
   - 明确区分真实趋势、低样本波动和 GSC 数据延迟。
4. **关键词排名与机会**
   - 列出主要曝光词、已有点击词、可见查询词的前 10/20/50 排名分布和机会词。
   - 解释哪些词正在增长、哪些词排名靠后、哪些词有曝光但 CTR 偏低。
   - 数据量小时明确标记“样本量较小”，避免过度解读。
5. **自然搜索着陆页表现**
   - 列出主要自然搜索着陆页，并判断核心产品页是否获得有效曝光。
   - 给出每个核心页面下一步应覆盖的搜索意图和内部链接建议。
6. **索引与多语言风险**
   - 评价英文首页、两款核心产品页、简体中文和繁体中文首页。
   - 只报告会影响抓取、收录和排名的问题：异常状态码、英文 URL 跳转到中文、noindex、canonical/hreflang 冲突、robots 或 sitemap 异常。
   - 没有异常时用一段话简要说明，不展开页面速度或服务器状态。
7. **下一步 SEO 优化行动**
   - 按 P0、P1、P2 排序，每项包含：问题、证据、具体动作、预期 SEO 影响、建议完成时间。
   - 优先给出能够提升收录、曝光、排名和 CTR 的动作，不要给泛泛建议。
8. **数据边界**
   - 说明 GSC 匿名查询、低样本和数据延迟对结论的限制。
   - 外部平台品牌可见性尚未接入时只写“未接入外部搜索数据”，不要提出 PageSpeed、转化追踪或其他偏离搜索排名的接入建议。

将完整报告写入 `monitor/reports/weekly-latest.md`，并把同一份中文报告作为最终回复。
